# AI運用標準と既存プロジェクトルール

## 共通AI運用標準 v1.0

標準バージョン: v1.0
最終更新: 2026-10-13
制定根拠: ユーザー指定の全プロジェクト共通標準

### 役割と正本

- Google Driveは業務仕様の正本。
- ChatGPTは業務仕様の確認・整理とCodexへの作業指示作成を担当する。
- Codex Cloudは指示された範囲の実装・修正・テストを担当する。
- GitHubはソースコードと開発成果の正本。Cloud専用Repoと元のコード正本Repoの区別は既存の固有ルールに従う。
- CodexからGoogle Driveへ直接アクセスしない。必要な仕様・共通ルールはChatGPT経由の作業指示、または提供済みの読取専用スナップショットで確認する。参照元・版・更新日時は提供情報の範囲で記録し、不明な情報は「未確認」とする。Driveの最新版を確認したと推測で報告しない。

### 作業と完了条件

- 作業前にAGENTS.md、README、関連コード、既存テスト、設定、現在差分と影響範囲を確認する。
- 既存機能を壊さず、指示された目的を最小変更で達成する。指示外の仕様・UI・データ構造・依存関係を変更しない。
- 変更後のテスト・検証は必須。実装変更は固有の検証手順で正常系・異常系・境界値・既存機能を確認する。文書のみの変更は差分・参照・固有ルールの保持・実装不変を検証する。未実施・失敗・実機未確認は明記し、合格扱いしない。
- 検証結果と変更理由を記録し、成果をGitHubの作業ブランチ・コミット・PRへ残す。既存のブランチ・レビュー・承認条件を守る。PR作成とmerge、本番反映は別の操作として報告する。

### 既存ルールとの統合・優先関係

- 下記の既存本文とプロジェクト固有ルールは削除しない。技術、データ列、計算・判定、保存、フォント、互換性、検証コマンド、バックアップ、接続禁止、実データ持込禁止、承認条件を維持する。
- 共通運用について旧本文・AGENTS_common.md・snapshot・起動スキル等と矛盾する場合は、本標準v1.0を適用する。特に旧「作業開始時にDrive正本を取得する」は旧手順として適用せず、ChatGPT経由の提供情報を使う。旧パスや同名ファイルだけで最新版・正本と判断しない。
- この優先関係は共通運用の矛盾に限る。固有のデータ境界・接続禁止・mergeやIIS反映の承認条件を緩めない。共通標準の統合は元Repoへの接続、実データ取得、merge、本番配置、削除の許可を意味しない。
- プロジェクト固有ルール同士の未解決の矛盾は報告し、既存実装を保持する。今回の統合だけを理由にアプリ仕様を選び直さない。
- 共通標準はプロジェクト単位で無断改変しない。改定時は版・日付・理由を記録して対象Repoごとに差分確認する。Drive文書の更新だけでRepoへ自動反映されたとは扱わない。

## 既存本文（固有ルール保持・旧共通手順は上記優先関係に従う）

# AGENTS.md

> Codex / Gemini / その他のエージェント用の起点ファイルです。
> この Vault のルールは [`CLAUDE.md`](CLAUDE.md) に集約されています。**まず CLAUDE.md を読んでから作業を始めてください。**

## 最低限ここだけは守る

1. セッション開始時に `CLAUDE.md` → `rules/corrections.md` → `rules/mistakes.md` → `wiki/index.md` を読む。
2. オーナーに訂正されたら `rules/corrections.md` に3行で追記する（次回以降も守る）。
3. `raw/` は読むだけ（削除・改名しない）。構造化した知識は `wiki/` に書く。
4. 答えは `reports/` にファイルで残し、`wiki/` ページにリンクする。
5. 破壊的操作（削除・上書き・大量改名）の前は確認する。
6. 日付・数値・固有名詞は確証がなければ「未確認」と明示する。

詳細はすべて [`CLAUDE.md`](CLAUDE.md) に従うこと。
